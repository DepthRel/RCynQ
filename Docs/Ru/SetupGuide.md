# Руководство по настройке RCynQ

[English](../En/SetupGuide.md) · [Deutsch](../De/SetupGuide.md) · [Español](../Es/SetupGuide.md) · [Français](../Fr/SetupGuide.md) · [Português](../Pt/SetupGuide.md) · **Русский**

Участвуют три компьютера:

| Узел | Компьютер |
|---|---|
| **Workstation** | на котором вы правите проект |
| **Origin** | на котором лежат закрытые репозитории |
| **Relay** | до которого дотягиваются оба остальных |

Выполняйте шаги по порядку. Там, где у шага есть варианты, выберите подходящий для этого компьютера.

## 1. Проверьте, кто кого видит

| Откуда | Куда | Порт |
|---|---|---|
| Workstation | Relay | 22 |
| Origin | Relay | 22 |
| Relay | Origin | 22 (вариант A из шага 3) или 18444 (вариант B) |
| Relay | Workstation | 22 (вариант A) или 18444 (вариант B) |

Как компьютеры видят друг друга (локальная сеть, любой VPN, публичный адрес) — решать вам; RCynQ нужно только, чтобы адреса отвечали. Запишите адрес каждого компьютера таким, каким его видит сосед.

**Без узла Relay.** Если Workstation и Origin видят друг друга напрямую, пропустите шаг 4 и все упоминания Relay.

## 2. Установите программу

На каждом компьютере один из вариантов:

| Система | Пакет | Где хранятся настройки и данные |
|---|---|---|
| Windows | `RCynQ-<версия>-setup.exe`: ставит программу для текущего пользователя в `%LOCALAPPDATA%\Programs\RCynQ`, без прав администратора | `config` и `data` внутри папки установки |
| Windows | `RCynQ-<версия>-win-x64.zip`: распакуйте в папку, куда можно писать, например `C:\RCynQ`, не в `Program Files` | `config` и `data` рядом с программой |
| Debian, Ubuntu | `RCynQ-<версия>-linux-x64.deb`: `sudo apt install ./RCynQ-<версия>-linux-x64.deb`; Git и SSH-клиент ставятся вместе с ним | `~/.config/RCynQ` и `~/.local/share/RCynQ` каждого пользователя |
| Linux, macOS | `RCynQ-<версия>-<платформа>.tar.gz`: распакуйте в папку, куда можно писать, например `~/rcynq` | `config` и `data` рядом с программой |

Затем запустите RCynQ: из меню «Пуск» или `RCynQ.exe` (Windows), из меню приложений или `rcynq-ui` (`.deb`),
`./RCynQ.sh` (архивы для Linux и macOS). То же написано в `README.txt` пакета для его системы.

На узлах Workstation и Origin установите Git и проверьте: `git --version`.

Для каждого компьютера берите чистый пакет. Не копируйте папку, в которой RCynQ уже запускался: её папки `config` и `data` — это «личность» того узла.

## 3. Выберите, как узел принимает подключения

Relay всегда использует вариант A. Для Workstation и Origin выбирайте отдельно для каждого компьютера.

### Вариант A — SSH-сервер

**Windows** (PowerShell от имени администратора):

```powershell
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Set-Service -Name sshd -StartupType Automatic
Start-Service sshd
```

Если первая команда завершилась ошибкой `0x800f0954`, установите `OpenSSH-Win64-*.msi` со страницы [релизов Win32-OpenSSH](https://github.com/PowerShell/Win32-OpenSSH/releases) командой `msiexec /i <файл> ADDLOCAL=Server`, запустите службу как выше и откройте порт:

```powershell
New-NetFirewallRule -Name sshd -DisplayName 'OpenSSH Server (sshd)' -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22
```

**Linux:**

```bash
sudo apt install openssh-server      # или: sudo dnf install openssh-server
sudo systemctl enable --now ssh      # в Fedora и RHEL служба называется sshd
```

**macOS:** «Системные настройки» → «Основные» → «Общий доступ» → «Удалённый вход».

Проверка: `ssh -V` печатает версию, служба запущена (`Get-Service sshd` / `systemctl status ssh`).

### Вариант B — собственный TLS-порт, без SSH-сервера

Для компьютера, на который SSH-сервер поставить нельзя. Откройте входящий TCP-порт `18444`.

**Windows** (PowerShell от имени администратора):

```powershell
New-NetFirewallRule -Name rcynq -DisplayName 'RCynQ' -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 18444
```

**Linux:** `sudo ufw allow 18444/tcp` или `sudo firewall-cmd --permanent --add-port=18444/tcp && sudo firewall-cmd --reload`.

SSH-*клиент* на этом компьютере всё равно нужен, если используется Relay: `ssh -V`.

## 4. Настройте Relay

1. Запустите RCynQ. В окне настройки укажите идентификатор узла (например, `relay-1`), роль **Relay** и сохраните.
2. **«Роль и узлы» → «Экспортировать конфигурацию».** Выберите адрес, по которому Relay виден узлу Workstation, и сохраните `relay-for-workstation.rcynq.json`.
3. Экспортируйте ещё раз с адресом, по которому Relay виден узлу Origin: `relay-for-origin.rcynq.json`. Если адрес один и тот же, хватит одного файла.

## 5. Настройте Origin

1. Запустите RCynQ. В окне настройки укажите:
   - идентификатор узла, например `origin-1`;
   - роль **Origin**;
   - папку Git-репозитория (ту, в которой лежит `.git`);
   - **«Как соседи подключаются к этому узлу»** — «Через SSH-сервер этого компьютера» (вариант A) или «Без SSH-сервера: собственный порт с TLS» (вариант B).
2. Скопируйте созданный **общий link-токен**. Такой же нужен на узле Workstation.
3. Сохраните.
4. **«Роль и узлы» → «Экспортировать конфигурацию».** Создайте ключ, если программа предложит, выберите адрес, по которому Origin виден узлу Relay, сохраните `origin.rcynq.json`.

Репозиторий получает имя своей папки. Под этим именем его увидит Workstation.

## 6. Настройте Workstation

1. Запустите RCynQ. В окне настройки укажите:
   - идентификатор узла, например `workstation-1`;
   - роль **Workstation**;
   - папку для рабочей копии. Подойдёт пустая: первый Pull её заполнит;
   - **общий link-токен**, скопированный с узла Origin;
   - **«Как соседи подключаются к этому узлу»** — вариант A или B, как в шаге 3.
2. Сохраните.
3. **«Роль и узлы» → «Экспортировать конфигурацию».** Создайте ключ, если программа предложит, выберите адрес, по которому Workstation виден узлу Relay, сохраните `workstation.rcynq.json`.

## 7. Обменяйтесь файлами узлов

На каждом компьютере: **«Роль и узлы» → «Импортировать конфигурацию»**, в таком порядке.

| На узле | Импортировать |
|---|---|
| Workstation | `relay-for-workstation.rcynq.json`, затем `origin.rcynq.json` |
| Origin | `relay-for-origin.rcynq.json`, затем `workstation.rcynq.json` |
| Relay | `workstation.rcynq.json` и `origin.rcynq.json` |

Без узла Relay: Workstation импортирует `origin.rcynq.json`, Origin импортирует `workstation.rcynq.json`.

Закрытых ключей в файлах нет. Передавайте их по каналу, которому доверяете.

## 8. Разрешите подключения

После каждого импорта RCynQ предлагает разрешить ключ соседа.

- **Вариант A:** подтвердите. В Windows подтвердите и запрос прав администратора. Ключу разрешён проброс одного порта, выполнять команды он не может.
- **Вариант B:** делать ничего не нужно, SSH-сервера нет.

Если вы отказались, нажмите **«Роль и узлы» → «Разрешить подключения узлов»**.

## 9. Проверьте и выполните Pull

1. На узлах Workstation и Origin: **«Диагностика» → «Запустить проверку»**. Исправьте красное; каждая непройденная проверка говорит, как.
2. На узле Workstation: **«Ветки» → «Pull с Origin»**. В папке появился проект.
3. Измените файл, откройте **«Синхронизация»**, нажмите **«Отправить изменения»**. Файл появился на узле Origin.

Дальше: **Pull** — получить новые коммиты, **«Отправить изменения»** — доставить свои правки. Изменения, сделанные на узле Origin, отправляются оттуда так же.

## 10. Несколько репозиториев

1. На узле Origin: **«Ветки» → «Добавить репозиторий»**, выберите папку другого Git-репозитория.
2. На любом узле выберите репозиторий в списке вверху окна. Узел переключается без перезапуска.
3. На узле Workstation репозиторий, которого на компьютере ещё нет, спросит папку и сам выполнит Pull.
4. Второй узел покажет уведомление: **«Перейти»** или **«Остаться»**. Обмен изменениями идёт, только пока оба узла работают с одним репозиторием.

Командная строка: `rcynq repo list`, `rcynq repo add <имя> <путь>`, `rcynq repo use <имя>`, `rcynq repo remove <имя>`.

Удаление репозитория из списка никогда не удаляет его папку и файлы.

## 11. Запасные маршруты и несколько узлов Relay

Если узел этой роли уже есть в цепочке, импорт ничего не меняет молча, а спрашивает, чем является файл.

| Что импортируется | Варианты |
|---|---|
| Тот же узел с другим адресом | **Альтернативный маршрут** — адрес добавляется к маршрутам узла. **Замена** — новый адрес занимает место используемого |
| Другой узел Relay | **Ещё один узел** — Relay добавляется в цепочку перед конечным узлом. **Замена** — занимает место выбранного узла Relay |
| Другой конечный узел | Только **Замена**: цепочка заканчивается одним узлом |

Заменённый узел забывается вместе с ключами. После замены нажмите **«Разрешить подключения узлов»**, чтобы его ключ потерял доступ.

**Запасной маршрут.** Пример: два компьютера связаны туннелем AmneziaWG поверх UDP, рядом поднят туннель поверх TCP.

1. На соседнем узле экспортируйте конфигурацию ещё раз, выбрав адрес второго туннеля.
2. Импортируйте файл и выберите **«Альтернативный маршрут»**.
3. Под узлом в списке **«Узлы цепочки»** появятся маршруты с их состоянием и задержкой.

По умолчанию включён **«Автоматический выбор»**: используется самый приоритетный из отвечающих маршрутов, а среди равных — самый быстрый. Если маршрут перестал отвечать, трафик переходит на следующий; когда лучший снова отвечает, узел возвращается на него. Стрелки меняют приоритет (меньше — важнее). Отметка у маршрута закрепляет его вручную, пока вы не вернёте автоматический выбор.

Если путь идёт через узел Relay, импортируйте второй адрес и на нём: Relay разрешает проброс только к адресам, которые знает.

**Цепочка из двух узлов Relay** (`Workstation → Relay 1 → Relay 2 → Origin`).

1. На узлах Workstation и Origin импортируйте оба узла Relay; для второго выберите **«Ещё один узел»**. Порядок — порядок импорта, считая от этого узла.
2. На каждом узле Relay импортируйте соседний Relay и оба конечных узла.
3. На каждом узле нажмите **«Разрешить подключения узлов»**.

Командная строка: `rcynq import <файл> --as route|replace|hop [--link <звено>]`. Без `--as` такой импорт ничего не меняет и перечисляет варианты.

В `syncbridge.json` запасные адреса звена перечисляются в `Routes` (`Host`, необязательные `Name`, `SshPort`, `SshUser`, `Priority`); приоритет адреса самого звена — `RoutePriority`.

## Обновление с прежней версии

В прежних версиях роли назывались Source, Mediator и Dest. Теперь это Workstation, Relay и Origin.

1. Обновите **все** узлы одновременно: старая и новая версии друг друга не понимают.
2. Запустите каждый узел. Конфигурация преобразуется сама; прежний файл сохраняется как `syncbridge.json.bak`.
3. На узлах с SSH-сервером один раз нажмите **«Роль и узлы» → «Разрешить подключения узлов»**. Это перепишет старые строки ключей, которые разрешали больше, чем теперь нужно.

## Если что-то не работает

| Признак | Что проверить |
|---|---|
| Связь не в сети | Запустите **«Диагностику»** на этом узле. С соседа: `Test-NetConnection <адрес> -Port 22` (Windows) или `nc -vz <адрес> 22`. Для варианта B — порт `18444`. |
| «Общий ключ (link-токен) отсутствует или неверен» | Общий link-токен на узлах Workstation и Origin различается. Скопируйте его заново: **«Роль и узлы» → «Параметры узла»**. |
| Нет ключа узла | Экспортируйте его файл заново с флажком **«Включить публичный SSH-ключ узла»** и импортируйте. |
| «работает с репозиторием …, а патч предназначен для …» | Узлы работают с разными репозиториями. Переключите один из них. |
| Pull отказывает из-за локальных изменений | Перечисленные файлы изменены и не отправлены. Сначала отправьте их или отмените правки. |
| Изменился адрес узла | Экспортируйте его файл с новым адресом, импортируйте у соседей, нажмите **«Разрешить подключения узлов»**. |

Журналы — на вкладке **«Логи»** и в папке `data/logs`.
