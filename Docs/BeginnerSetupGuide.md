# RCynQ: пошаговая настройка для тех, кто не разбирается в сетях

Эта инструкция проведёт вас через настройку трёх компьютеров. Каждое действие расписано по шагам; все команды можно копировать и вставлять как есть — меняются только значения, выделенные `<угловыми скобками>`.

Инструкция написана для **Windows 10/11**. Если на каком-то компьютере Linux, отличия собраны в конце.

Подробный справочник по всем настройкам — в [UserGuide.md](UserGuide.md).

## 1. Что мы строим

Есть проект (Git-репозиторий), который лежит в закрытой сети — например, в офисе. Вы хотите работать над ним с другого компьютера, а изменения должны попадать в закрытую сеть и обратно.

Напрямую эти два компьютера друг друга не видят. Поэтому между ними ставится третий — **узел-посредник**. Это самостоятельный компьютер в сети передачи: проект он не хранит, содержимое изменений не видит и ни к одному из концов не «принадлежит». Его задача — пропускать через себя соединения.

```
┌──────────┐   канал 1    ┌────────────┐   канал 2    ┌──────────┐
│  SOURCE  │ ───────────▶ │  MEDIATOR  │ ───────────▶ │   DEST   │
│ где вы   │              │ посредник  │              │ где лежит│
│ работаете│ ◀─────────── │            │ ◀─────────── │  проект  │
└──────────┘              └────────────┘              └──────────┘
```

| Компьютер | Роль в RCynQ | Что это |
|-----------|--------------|---------|
| Тот, где вы редактируете проект | **SOURCE** | Здесь вы работаете. |
| Отдельный компьютер, который видят оба конца | **MEDIATOR** | «Мост». Проект не хранит, содержимое изменений не видит — только пропускает соединения. |
| Тот, где лежит проект | **DEST** | Принимает ваши изменения и отдаёт свои. |

Все три компьютера физически разные и могут стоять в разных сетях, городах и организациях. Важно только то, кто кого видит по сети:

| Кто подключается | К кому | Зачем |
|------------------|--------|-------|
| SOURCE | MEDIATOR, порт 22 | отправить изменения в сторону DEST |
| DEST | MEDIATOR, порт 22 | отправить изменения в сторону SOURCE |
| MEDIATOR | DEST, порт 22 **или** порт RCynQ `18444` | пропустить SOURCE к DEST |
| MEDIATOR | SOURCE, порт 22 **или** порт RCynQ `18444` | пропустить DEST к SOURCE |

**Как узел принимает подключения — выбираете вы, для каждого конечного узла отдельно:**

| Способ | Что нужно на компьютере | Когда выбирать |
|--------|------------------------|----------------|
| **Через SSH-сервер** (порт 22) | Включённый SSH-сервер Windows | Обычный случай |
| **Без SSH-сервера** (порт RCynQ `18444`) | Только разрешение порта в брандмауэре | SSH-сервер установить нельзя — например, корпоративный компьютер с запретом политикой |

Посреднику (MEDIATOR) **SSH-сервер нужен всегда**: именно через него проходят соединения соседей. Во втором способе посредник только передаёт зашифрованный трафик до порта RCynQ; шифрование устанавливается напрямую с конечным узлом, и содержимое изменений посредник не видит в обоих способах.

Каким способом это устроено, RCynQ безразлично: VPN, локальная сеть, публичный адрес, маршрутизация между сетями. В примерах этой инструкции SOURCE видит MEDIATOR через VPN, а MEDIATOR видит DEST по локальной сети — **это только пример**, каналы у вас могут быть любыми.

Как это работает для вас: вы меняете файлы на SOURCE, нажимаете «Отправить изменения» — и они появляются на DEST. Изменения, сделанные на DEST, приходят обратно так же.

> **Всё хранится в папке программы.** Настройки, база, ключи и журналы RCynQ лежат внутри папки, куда вы распаковали программу (`C:\RCynQ`). Удалили папку — от RCynQ ничего не осталось. Вне этой папки меняются только две вещи, которые принадлежат Windows, а не RCynQ: встроенный SSH-сервер (шаг 0.2) и список разрешённых ключей для него (шаг 5, программа заполняет его сама).

## 2. Несколько слов, которые встретятся

| Слово | Простыми словами |
|-------|------------------|
| **IP-адрес** | «Номер дома» компьютера в сети, например `192.168.10.20`. У одного компьютера может быть несколько адресов — по одному на каждую сеть, к которой он подключён: например, один в локальной сети, другой в VPN. |
| **VPN** | «Защищённый коридор» через интернет. Компьютеры в одной VPN видят друг друга, как будто стоят рядом. У VPN-адресов свой вид, например `10.8.1.2`. |
| **Порт** | «Номер двери» в компьютере. SSH-сервер слушает дверь `22`. RCynQ держит дверь `18443` только для себя (для окна программы) и, если узел работает без SSH-сервера, открывает для соседей дверь `18444`. |
| **SSH** | Способ безопасно подключиться к другому компьютеру. RCynQ пользуется им, чтобы доставлять изменения через посредника. |
| **SSH-сервер (sshd)** | Программа, которая «открывает дверь» и пускает разрешённые подключения. Входит в Windows, её нужно только включить (шаг 0.2). Если на компьютере его поставить нельзя — см. шаг 0.4. |
| **SSH-клиент** | Программа `ssh`, которой RCynQ сам подключается к соседям. В Windows 10/11 установлена по умолчанию, отдельно от SSH-сервера. |
| **SSH-ключ** | Электронный «пропуск» компьютера. Бывает закрытая часть (секрет, никому не отдаётся) и публичная — одна строка текста, которую можно пересылать. |
| **Link-токен** | Общий пароль, одинаковый на SOURCE и DEST. Без него DEST не примет изменения. |

## 3. Что подготовить заранее

1. **Три компьютера** с Windows 10 или 11 и учётными записями с правами администратора. На MEDIATOR обязательно должен работать SSH-сервер. На SOURCE и DEST — либо SSH-сервер, либо разрешённый входящий порт `18444` (шаг 0.4).
2. **Связь между SOURCE и MEDIATOR в обе стороны.** Чем она обеспечена — ваше дело: чаще всего это VPN, которую настраивает администратор или приложение AmneziaVPN. В этой инструкции связь считается уже работающей.
   Проверка: в пункте 5.2 вы узнаете адрес MEDIATOR, а в пункте 7.1 проверите с SOURCE, что он отвечает.
3. **Связь между MEDIATOR и DEST в обе стороны.** Например, оба в одной локальной сети, или DEST доступен посреднику через свою VPN либо маршрутизацию. MEDIATOR не обязан стоять рядом с DEST — достаточно, чтобы он до него дозванивался.
4. **Архив программы RCynQ** — файл `RCynQ-win-x64.zip` из `artifacts\publish` после сборки или то, что вам прислали. В этом архиве нет ничьих настроек, поэтому один и тот же архив подходит для всех трёх компьютеров.
5. **Git** на SOURCE и DEST. Проверка: откройте PowerShell и выполните `git --version`. Если команда не найдена, установите Git for Windows с сайта git-scm.com, соглашаясь со всеми вариантами по умолчанию.
6. **Таблица адресов.** Перепишите её в блокнот и заполняйте по ходу — дальше везде будут ссылки на эти строки:

| № | Что | Пример | Ваше значение |
|---|-----|--------|---------------|
| А1 | Адрес MEDIATOR, по которому его видит SOURCE | `10.8.1.2` | |
| А2 | Адрес MEDIATOR, по которому его видит DEST | `192.168.10.5` | |
| А3 | Адрес DEST, по которому его видит MEDIATOR | `192.168.10.20` | |
| А4 | Адрес SOURCE, по которому его видит MEDIATOR | `10.8.1.3` | |
| П1 | Имя пользователя Windows на MEDIATOR | `office` | |
| П2 | Имя пользователя Windows на DEST | `builder` | |
| П3 | Имя пользователя Windows на SOURCE | `dev` | |
| Т | Link-токен | длинная строка | |

Если MEDIATOR подключён к одной сети и виден обоим концам по одному и тому же адресу, А1 и А2 совпадают — так тоже правильно.

## 4. Шаг 0. Установка на каждый компьютер

Сделайте этот шаг на **всех трёх** компьютерах.

### 0.1. Распаковать программу

1. Создайте папку **`C:\RCynQ`**. В пути не должно быть пробелов и русских букв.
   Не кладите программу в `C:\Program Files`: туда обычные программы не могут записывать свои данные.
2. Распакуйте архив: правый клик по `RCynQ-win-x64.zip` → «Извлечь все…». Внутри лежит папка `RCynQ` — скопируйте **её содержимое** в `C:\RCynQ`. Должно получиться так:

   ```
   C:\RCynQ\
     RCynQ.exe          ← запуск программы
     rcynq.portable     ← метка «хранить всё в этой папке»
     cli\  dbmigrator\  service\  ui\
   ```

3. Запускайте программу файлом **`RCynQ.exe`** — у него иконка RCynQ, и он работает из любой папки. Для удобства сделайте ярлык на рабочем столе: правый клик по `C:\RCynQ\RCynQ.exe` → «Отправить» → «Рабочий стол (создать ярлык)».

> **Не копируйте папку, в которой программа уже запускалась.** После первого запуска в ней появляются папки `config` и `data` — это «личность» узла: его имя, ключи и список соседей. Если перенести их на другой компьютер, два компьютера будут выдавать себя за один узел. Для нового компьютера всегда берите чистый архив. Если вы всё же скопировали такую папку, программа предупредит об этом при запуске.

### 0.2. Включить SSH-сервер Windows

Этот пункт обязателен на MEDIATOR. На SOURCE и DEST — по желанию: если SSH-сервер там не ставится или запрещён, пропустите 0.2 и 0.3 и сразу переходите к **0.4**.

1. Нажмите «Пуск», введите `PowerShell`, правый клик → **«Запуск от имени администратора»**.
2. Скопируйте и выполните по очереди:

   ```powershell
   Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
   Set-Service -Name sshd -StartupType Automatic
   Start-Service sshd
   ```

   Первая команда может выполняться несколько минут. Если она завершилась ошибкой **`0x800f0954`** (частое дело на корпоративных компьютерах), перейдите к пункту 0.3 — там способ установить SSH-сервер без Windows Update.
3. Проверьте, что SSH-сервер работает:

   ```powershell
   Get-Service sshd
   ```

   В колонке `Status` должно быть **`Running`**.
4. Узнайте имя пользователя Windows и запишите его в таблицу (П1, П2 или П3 — для этого компьютера):

   ```powershell
   $env:USERNAME
   ```

При установке SSH-сервер сам добавляет разрешение в брандмауэр Windows, отдельно ничего открывать не нужно.

### 0.3. Если `Add-WindowsCapability` не сработала

Ошибка **`0x800f0954`** означает, что компьютер получает обновления с внутреннего сервера организации (WSUS), а компонент OpenSSH там не опубликован. Сам по себе SSH-сервер при этом не запрещён — Windows просто негде его взять. Порядок действий:

1. Проверьте, вдруг он уже установлен:

   ```powershell
   Get-WindowsCapability -Online -Name OpenSSH.Server*
   ```

   Если в `State` написано `Installed`, вернитесь к пункту 0.2 с команды `Set-Service`.
2. **Спросите системного администратора.** Правильный путь в организации — попросить установить OpenSSH Server. Ему достаточно либо разрешить загрузку дополнительных компонентов напрямую из Windows Update, либо дать ISO-образ «Features on Demand» для вашей сборки Windows; тогда команда выполняется так:

   ```powershell
   Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0 -Source D:\ -LimitAccess
   ```

   Если установка SSH-сервера на этом компьютере не разрешена или не получается — это не препятствие: переходите к пункту 0.4.
3. **Установка из официального установщика Microsoft.** Проект [Win32-OpenSSH](https://github.com/PowerShell/Win32-OpenSSH/releases) — тот же самый OpenSSH, что входит в Windows, только отдельным файлом `OpenSSH-Win64-vX.Y.Z.msi`. Windows Update ему не нужен. В PowerShell **от имени администратора**:

   ```powershell
   msiexec /i C:\Downloads\OpenSSH-Win64-v9.8.1.0.msi ADDLOCAL=Server
   Set-Service -Name sshd -StartupType Automatic
   Start-Service sshd
   New-NetFirewallRule -Name sshd -DisplayName 'OpenSSH Server (sshd)' -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22
   ```

   Имя файла подставьте из скачанного релиза. Дальше всё как обычно: файлы настроек лежат в `C:\ProgramData\ssh`, и автоматическая выдача разрешений (шаг 5) работает без изменений.

> Менять политику обновлений компьютера (ключ `UseWUServer` в реестре) ради установки компонента не стоит: на корпоративной машине это обходит правила ИТ-службы, а политика всё равно вернётся при следующем обновлении групповых политик.

### 0.4. Компьютер без SSH-сервера (только SOURCE или DEST)

Если SSH-сервер на компьютере не ставится, RCynQ откроет для соседей собственный порт `18444` с шифрованием TLS. Проверку, что к узлу подключается именно он, соседи делают по отпечатку его сертификата — отпечаток попадёт в файл экспорта автоматически.

1. **Проверьте, что есть SSH-клиент** — он нужен, чтобы этот узел сам отправлял изменения через посредника. В обычном PowerShell:

   ```powershell
   ssh -V
   ```

   Должна появиться строка вида `OpenSSH_for_Windows_9.5p1`. Клиент входит в Windows 10/11 и ставится отдельно от сервера, поэтому ошибка `0x800f0954` его не касается.
2. **Разрешите порт `18444` в брандмауэре.** PowerShell **от имени администратора**:

   ```powershell
   New-NetFirewallRule -Name rcynq -DisplayName 'RCynQ' -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 18444
   ```

   Если брандмауэром управляет ИТ-служба, попросите открыть входящий TCP-порт `18444` для адреса посредника.
3. **При первом запуске программы** (шаг 2.1 для DEST или 3.3 для SOURCE) в поле **«Как соседи подключаются к этому узлу»** выберите **«Без SSH-сервера: собственный порт с TLS»**. Порт оставьте `18444`. Уже настроенный узел переключается там же, на вкладке «Роль и узлы» → «Параметры узла».

Что не работает без SSH-сервера на DEST: вкладка **«Ветки»** (получение веток Git с DEST) — Git забирает ветки только через SSH. Отправка и приём изменений работают полностью.

## 5. Шаг 1. Настраиваем MEDIATOR

Все действия — на компьютере-посреднике.

### 1.1. Первый запуск

1. Запустите `RCynQ.exe`. Откроется окно **«Настройка узла RCynQ»**.
2. Заполните:
   - **Идентификатор узла:** `mediator-1`.
   - **Отображаемое имя:** например, `Посредник`.
   - **Роль узла:** **Mediator**.
   - **Порт сервиса:** оставьте `18443`.
3. Нажмите **«Сохранить и запустить»**.

Внизу окна появится «сервис запущен приложением». Больше на MEDIATOR ничего запускать не нужно: пока открыта программа, работает и узел. Закроете программу — узел остановится.

### 1.2. Узнать адреса MEDIATOR

1. Откройте вкладку **«Роль и узлы»** → **«Экспортировать конфигурацию»**.
2. Программа сама проверит компьютер и покажет список адресов — у посредника их обычно несколько, по одному на каждую сеть, к которой он подключён. Найдите:
   - адрес в той сети, через которую MEDIATOR связан с SOURCE (в примере это VPN, пометка **«VPN / туннель»**) → запишите в **А1**;
   - адрес в той сети, через которую MEDIATOR связан с DEST (в примере это локальная сеть, пометка **«локальная сеть»**) → запишите в **А2**.
   Если адрес всего один, он же и А1, и А2.
3. Проверьте строку «SSH-сервер принимает подключения». Если там крестик — вернитесь к шагу 0.2.
4. Предупреждение «SSH-ключ узла не найден» на MEDIATOR **можно не обращать внимания**: посреднику собственный ключ не нужен.

### 1.3. Сохранить два файла MEDIATOR

SOURCE и DEST могут видеть MEDIATOR по разным адресам, поэтому файлов тоже два. Если А1 и А2 совпадают, сделайте один файл и импортируйте его на обоих компьютерах.

1. **Файл для SOURCE.** В диалоге экспорта выберите в списке адрес **А1** → «Экспортировать» → сохраните как `mediator-for-source.rcynq.json`.
2. **Файл для DEST.** Снова «Экспортировать конфигурацию» → выберите адрес **А2** → «Экспортировать» → сохраните как `mediator-for-dest.rcynq.json`.

Эти файлы понадобятся на шаге 4. Закрытых ключей в них нет, но передавайте их только по доверенному каналу: флешка, рабочая почта или мессенджер внутри компании.

## 6. Шаг 2. Настраиваем DEST

Все действия — на компьютере, где лежит проект.

### 2.1. Первый запуск

1. Запустите `RCynQ.exe` и заполните окно настройки:
   - **Идентификатор узла:** `dest-1`.
   - **Роль узла:** **Dest**.
   - **Путь к репозиторию:** кнопка «Обзор…» → папка проекта (та, в которой есть скрытая папка `.git`).
   - **Общий link-токен:** уже заполнен случайной строкой. **Скопируйте её в таблицу, строка Т.** Эта же строка понадобится на SOURCE.
   - **Как соседи подключаются к этому узлу:** «Через SSH-сервер этого компьютера», если сделали шаг 0.2, или «Без SSH-сервера: собственный порт с TLS», если шаг 0.4.
2. Нажмите **«Сохранить и запустить»**.

Ключ потом всегда можно посмотреть и скопировать: вкладка **«Роль и узлы»** → блок **«Параметры узла»** → кнопки «Показать» и «Копировать».

### 2.2. Создать файл DEST

1. **«Роль и узлы»** → **«Экспортировать конфигурацию»**.
2. Если написано «SSH-ключ не найден», нажмите **«Создать ключ»** и подождите пару секунд.
3. Выберите адрес в той сети, через которую DEST виден с MEDIATOR, и запишите его в **А3**.
4. Флажок «Включить публичный SSH-ключ узла» оставьте включённым.
   - Если DEST работает через SSH-сервер, оставьте включённым и «Включить отпечаток ключа хоста sshd».
   - Если DEST работает без SSH-сервера, вместо этого флажка диалог показывает **отпечаток TLS-сертификата** и строку «Узел без SSH-сервера: соседи подключаются к порту RCynQ 18444». Отпечаток попадёт в файл сам.
5. «Экспортировать» → сохраните как `dest.rcynq.json`.

## 7. Шаг 3. Настраиваем SOURCE

Все действия — на компьютере, где вы редактируете проект.

### 3.1. Проверить, что MEDIATOR виден с SOURCE

Если для связи с MEDIATOR нужна VPN, подключите её. Откройте PowerShell (обычный) и выполните, подставив адрес **А1**:

```powershell
Test-NetConnection <А1> -Port 22
```

В ответе должно быть **`TcpTestSucceeded : True`**. Если `False`, SOURCE не видит MEDIATOR — дальше идти бессмысленно, смотрите раздел 11.

### 3.2. Получить копию проекта

При первой настройке проект на SOURCE и на DEST должен быть **одинаковым**.

1. На **DEST** заархивируйте папку проекта целиком, вместе со скрытой папкой `.git`: правый клик → «Отправить» → «Сжатая ZIP-папка».
2. Перенесите архив на SOURCE и распакуйте, например в `C:\Projects\app`.

### 3.3. Первый запуск

1. Запустите `RCynQ.exe` и заполните окно настройки:
   - **Идентификатор узла:** `source-1`.
   - **Роль узла:** **Source**.
   - **Рабочая копия:** «Обзор…» → распакованная папка проекта.
   - **Общий link-токен:** сотрите сгенерированную строку и **вставьте строку Т** с DEST.
   - **Как соседи подключаются к этому узлу:** как на DEST — по тому, сделали вы шаг 0.2 или 0.4 на этом компьютере.
2. **«Сохранить и запустить»**.

### 3.4. Создать файл SOURCE

1. **«Роль и узлы»** → **«Экспортировать конфигурацию»** → при необходимости **«Создать ключ»**.
2. Выберите адрес с пометкой **«VPN / туннель»** и запишите его в **А4**.
3. Флажки «Включить публичный SSH-ключ узла» и «Включить отпечаток ключа хоста sshd» оставьте включёнными.
4. «Экспортировать» → сохраните как `source.rcynq.json`.

Публичный SSH-ключ внутри файлов SOURCE и DEST нужен соседям, чтобы на шаге 5 программа сама разрешила им подключаться.

## 8. Шаг 4. Обмениваемся файлами узлов

Теперь каждый узел должен «узнать» соседей. Для этого на каждом компьютере: **«Роль и узлы» → «Импортировать конфигурацию»** → выбрать файл.

| На каком компьютере | Какие файлы импортировать (по порядку) |
|---------------------|----------------------------------------|
| **SOURCE** | 1) `mediator-for-source.rcynq.json`, 2) `dest.rcynq.json` |
| **DEST** | 1) `mediator-for-dest.rcynq.json`, 2) `source.rcynq.json` |
| **MEDIATOR** | `source.rcynq.json` и `dest.rcynq.json` |

Порядок важен: сначала посредник, потом конечный узел.

После импорта в списке «Узлы цепочки» на SOURCE должно быть две строки: `MEDIATOR-1` и под ней `DEST-1`. На DEST — `MEDIATOR-1` и `SOURCE-1`.

Статус пока может быть «нет связи» — это нормально, соединения ещё не разрешены. Этим займёмся на следующем шаге.

## 9. Шаг 5. Разрешаем узлам подключаться друг к другу

SSH-сервер Windows пускает только те ключи, которые явно разрешены. RCynQ делает это **сам**, сразу после каждого импорта на шаге 4. Вводить ключи и адреса вручную не нужно.

### 5.1. Что вы увидите

После импорта программа проверит, кому из соседей нужно подключаться к этому компьютеру:

| На каком компьютере | Кому разрешается | Что разрешается |
|---------------------|------------------|-----------------|
| **MEDIATOR** | SOURCE и DEST | SOURCE — пройти только к DEST, DEST — только к SOURCE (к SSH-серверу соседа или к его порту RCynQ, смотря что он выбрал) |
| **DEST** | SOURCE | Только доставить изменения в RCynQ на DEST |
| **SOURCE** | DEST | Только доставить изменения в RCynQ на SOURCE |

На компьютере **без SSH-сервера** этот шаг не нужен вообще: разрешения записывать некуда, соседи подключаются к порту RCynQ. Программа так и скажет и не будет спрашивать права администратора.

Каждое разрешение ограничено: ключу позволено ровно одно действие, войти в систему или выполнить команду через него нельзя.

1. Если ваша учётная запись Windows — администратор (так почти всегда на домашних и рабочих компьютерах), появится окно **«Разрешить подключения узлов»** со списком действий. Нажмите **«Да»**.
2. Windows покажет запрос **«Разрешить этому приложению вносить изменения?»** — нажмите **«Да»**. Права администратора нужны, потому что Windows хранит разрешения администраторов в защищённом файле `C:\ProgramData\ssh\administrators_authorized_keys`.
3. Внизу вкладки появится **«Подключения соседних узлов разрешены»**.

Для учётной записи без прав администратора подтверждения не будет: разрешения сразу запишутся в профиль пользователя.

### 5.2. Сообщения, которые могут появиться

| Сообщение | Что делать |
|-----------|------------|
| «Для узла mediator… / source-1 импортируйте также файл второго конечного узла» | Нормально для MEDIATOR после первого импорта: разрешение SOURCE зависит от адреса DEST и наоборот. Импортируйте второй файл — сообщение исчезнет. |
| «В файле узла … нет SSH-ключа» | На том компьютере при экспорте был снят флажок ключа или ключ не был создан. Попросите экспортировать файл заново (шаг 2.2 или 3.4) и импортируйте его ещё раз. |
| «Подключения соседних узлов не разрешены» | Вы нажали «Нет» или отменили запрос Windows. Нажмите на вкладке «Роль и узлы» кнопку **«Разрешить подключения узлов»**. |

Кнопка **«Разрешить подключения узлов»** также пригодится, если адрес соседа изменился: импортируйте его новый файл и нажмите кнопку — старое разрешение будет заменено новым.

<details>
<summary>Для любопытных: что именно записывается</summary>

На MEDIATOR для ключа SOURCE появляется строка вида:

```
restrict,port-forwarding,permitopen="192.168.10.20:22",command="exit 1",no-pty,no-agent-forwarding,no-x11-forwarding ssh-ed25519 AAAA... rcynq:source-1
```

`permitopen` — единственный адрес, куда ключу можно пройти, `command="exit 1"` — запрет выполнять команды. Остальные строки файла программа не трогает. То же самое можно сделать без окна командой `C:\RCynQ\cli\rcynq.exe ssh allow` в PowerShell от имени администратора.

</details>

## 10. Шаг 6. Проверяем и делаем первую синхронизацию

### 6.1. Проверка связи

1. На **SOURCE** и на **DEST** откройте вкладку **«Диагностика»** → **«Запустить проверку»**.
   - Зелёные галочки — всё хорошо.
   - Красный крестик — прочитайте подсказку под ним и загляните в раздел 11.
2. На **SOURCE** откройте **«Туннель»** или **«Обзор»**: у звеньев должен быть статус **«онлайн»**.

### 6.2. Базовая копия

Базовая копия — «точка отсчёта», от которой считаются изменения. Создаётся **один раз**, пока проект на SOURCE и DEST одинаковый (после шага 3.2 так и есть).

1. На **DEST**: вкладка **«Синхронизация»** → **«Создать базовую копию»** → «Подтвердить».
2. На **SOURCE**: то же самое.

### 6.3. Первая отправка

1. На **SOURCE** создайте в папке проекта файл `rcynq-test.txt` с любым текстом.
2. **«Синхронизация»**: файл появится в списке «Изменения к отправке». Нажмите **«Отправить изменения»**.
3. На **DEST** проверьте, что файл `rcynq-test.txt` появился в папке проекта, а в «Истории патчей» есть строка «входящий — применён».
4. Проверьте обратное направление: измените файл на DEST и отправьте изменения оттуда.

Готово. Дальше работа выглядит так: меняете файлы → «Синхронизация» → «Отправить изменения».

Если одни и те же файлы изменены на обоих компьютерах, в истории появится строка «конфликт» с кнопкой **«Разрешить»**. Программа предложит:
- оставить свои файлы;
- взять присланные (ваши будут сохранены в резервную копию);
- объединить средствами Git.

## 11. Если что-то не работает

Самый полезный инструмент — команда в обычном PowerShell:

```powershell
Test-NetConnection <адрес> -Port <порт>
```

`TcpTestSucceeded : True` значит «до двери дошли, дверь открыта».

| Что видите | Что проверить |
|------------|---------------|
| Вверху окна «Сервис RCynQ недоступен» или «Не найден RCynQ.Service» | Программа распакована целиком (есть папки `service` и `ui` рядом). Нажмите «Повторить». |
| `Add-WindowsCapability` → `0x800f0954` | Компонент недоступен через внутренний сервер обновлений организации. Пункт 0.3: спросите администратора или поставьте OpenSSH установщиком MSI. |
| В экспорте «SSH-сервер не отвечает» | Шаг 0.2: `Get-Service sshd` должен показывать `Running`. |
| С SOURCE `Test-NetConnection <А1> -Port 22` → `False` | VPN не подключена на SOURCE или MEDIATOR, либо ошиблись адресом А1. Переподключите VPN и повторите экспорт на MEDIATOR (шаг 1.2). |
| С MEDIATOR `Test-NetConnection <А3> -Port 22` → `False` | DEST выключен, не в той сети или на DEST не запущен SSH-сервер (шаг 0.2). Если DEST работает без SSH-сервера, проверяйте порт `18444`, а не `22`. |
| С MEDIATOR `Test-NetConnection <А3> -Port 18444` → `False` | На DEST не запущена программа, в «Параметрах узла» не выбран режим «Без SSH-сервера» или порт не разрешён в брандмауэре (шаг 0.4). |
| В экспорте «порт RCynQ не отвечает» | То же, что строкой выше: программа, режим и брандмауэр на этом компьютере. |
| При отправке «The certificate presented by the peer does not match the fingerprint» | На принимающем узле пересоздан сертификат (например, удалили папку `data`). Экспортируйте его файл заново и импортируйте у соседей. |
| `ssh` не найден (`ssh -V` не работает) | На компьютере нет SSH-клиента. В Windows: «Параметры» → «Приложения» → «Дополнительные компоненты» → «Клиент OpenSSH», или попросите ИТ-службу. |
| Вкладка «Ветки» пишет, что DEST работает без SSH-сервера | Так и есть: ветки Git забираются только через SSH. Изменения при этом ходят нормально. |
| Звено «нет связи», в «Логах» `Permission denied` | На соседнем компьютере не разрешены подключения (шаг 5): откройте там «Роль и узлы» → «Разрешить подключения узлов». Проверьте также, что RCynQ там запущен под той же учётной записью Windows, что указана в его файле экспорта. |
| В «Логах» `administratively prohibited` | Адрес соседа изменился после импорта. Экспортируйте его файл заново, импортируйте и нажмите «Разрешить подключения узлов» на MEDIATOR. |
| Вверху окна «Папка программы скопирована с компьютера …» | Папку перенесли вместе с настройками другого узла. Если это новый узел — закройте программу, удалите папки `C:\RCynQ\config` и `C:\RCynQ\data` и настройте узел заново. Если вы переносите этот же узел на новый компьютер — нажмите «Это тот же узел». |
| При отправке «InvalidToken» | Link-токен на SOURCE и DEST разный. Закройте программу на SOURCE, откройте `C:\RCynQ\config\syncbridge.json` в Блокноте, замените значение после `"LinkToken":` на строку Т (в кавычках), сохраните и запустите программу снова. |
| При отправке «UnknownSender» | DEST не импортировал `source.rcynq.json` (шаг 4). |
| «Базовая копия не создана» | Шаг 6.2 на обоих компьютерах. |
| Каждое изменение уходит в «конфликт» | Проекты на SOURCE и DEST разошлись. Повторите шаг 3.2 (скопируйте проект заново) и шаг 6.2. |
| Отправилось, но на DEST файл не появился | Посмотрите «Синхронизация» → «История патчей» на DEST и «Логи». |

Где что лежит (всё внутри `C:\RCynQ`):

| Путь | Что там |
|------|---------|
| `config\syncbridge.json` | Настройки узла. |
| `data\rcynq.db` | База: узлы, история. |
| `data\keys\` | Ключи и токены. Не отправляйте никому, кроме файла `ssh\rcynq_ed25519.pub`. |
| `data\logs\` | Журналы — пригодятся, если просите помощи. |
| `data\backups\` | Ваши файлы, заменённые при разрешении конфликтов. |

| `data\installation.json` | Имя компьютера, на котором создан узел: по нему программа замечает копирование папки. |

**Три разных случая копирования:**

| Задача | Что копировать |
|--------|----------------|
| Поставить RCynQ на **ещё один** компьютер | Только чистый архив `RCynQ-win-x64.zip`. Или папку `C:\RCynQ` **без** `config` и `data`. |
| Сделать **резервную копию** этого узла | Закройте программу и скопируйте всю папку `C:\RCynQ`. |
| **Переехать** этим же узлом на новый компьютер | Закройте программу, скопируйте всю папку, на новом компьютере нажмите «Это тот же узел», затем экспортируйте файл узла заново (адрес изменился) и импортируйте его у соседей. На старом компьютере папку удалите. |

## 12. Если на компьютере Linux

Порядок действий тот же, отличаются только команды.

- **Программа:** распакуйте в `~/RCynQ` (сборка `linux-x64`). Запуск — `~/RCynQ/RCynQ.desktop` или `~/RCynQ/ui/RCynQ.UI`.
- **SSH-сервер (шаг 0.2):**

  ```bash
  sudo apt install -y openssh-server
  sudo systemctl enable --now ssh
  systemctl status ssh      # должно быть active (running)
  whoami                    # имя пользователя для таблицы
  ```

- **Проверка адреса (вместо Test-NetConnection):** `nc -vz <адрес> 22`.
- **Публичный ключ:** `~/RCynQ/data/keys/ssh/rcynq_ed25519.pub`.
- **Добавить разрешение (шаг 5.2):**

  ```bash
  KEY='<строка ключа>'
  ALLOW='<разрешение из таблицы>'
  mkdir -p ~/.ssh && chmod 700 ~/.ssh
  echo "restrict,port-forwarding,permitopen=\"$ALLOW\",command=\"exit 1\",no-pty,no-agent-forwarding,no-x11-forwarding $KEY" >> ~/.ssh/authorized_keys
  chmod 600 ~/.ssh/authorized_keys
  ```
