How it works

Two buttons instead of a commit and a push

One program takes one of three roles on each computer. You keep working where you are; RCynQ moves the code.

  1. Edit where you are

    Work in your usual editor on the Workstation. No WIP commits, no branches to clean up later.

  2. Send changes

    The edits leave as a patch: a signed manifest, then every file by its SHA-256.

  3. Applied as a whole

    The Origin applies everything or nothing. A conflict is shown file by file: keep, take, merge with Git or merge in your own merge tool (VS Code, Visual Studio, JetBrains, KDiff3, Meld…).

  4. Pull it back

    One button brings the current branch as an incremental Git bundle, even into an empty folder.

Workstation

The computer you work on. Keeps the working copies, sends changes, pulls branches.

Relay

Any computer both ends can reach. Forwards SSH, has no repository and sees no content.

Origin

The computer with the private repositories. RCynQ only reads them; only your patches change files there.

Relay services

Your code goes where you cannot

The repository sits in a closed network, your laptop is somewhere else. Put a Relay between them: a cloud VM, a bastion host, an office gateway, a teammate's machine.

  • A chain passes as many Relays as the road needs: Workstation → Relay 1 → Relay 2 → Origin.
  • A Relay stays passive. Its key in authorized_keys may forward one port and run no command.
  • Traffic is encrypted end to end; the Relay never sees a file, a branch or a repository path.
  • A node can have spare routes, for example two tunnels. RCynQ checks them every 15 seconds and moves to the one that answers.

Why RCynQ

Quick to set up, careful with your code

Built for closed networks, where the code must arrive and nothing else may leak.

⚡

No commits, no pushes

Work in progress travels as a patch. The history stays yours: nothing to squash, nothing to force-push.

🛰️

Through any Relay

One hop or several. Any machine with an SSH server both sides reach is enough.

🔏

Nothing to trust in the middle

Patches are signed with ECDSA P-256, accepted once and checked to stay inside the working tree.

🧊

The Origin stays clean

No remotes, refs, settings or commits are written into its repository. Only your files change.

🔀

Routes that heal

Several addresses for one node, the fastest one that answers is used, and it comes back when the better one returns.

🚪

No SSH server? Fine

An end node can accept connections on its own TLS port, verified by a pinned certificate.

📚

Many repositories

Register as many as you need on the Origin and switch between them from either side, without a restart.

🎒

Portable

Settings, keys and data stay in the program folder. Nothing is scattered over the system.

⌘

Window or terminal

A desktop application for every day and the rcynq command line for scripts.

Getting started

From three bare computers to the first Pull

No server to rent from us, no account, no cloud in the middle: only your machines.

  1. Install

    Put RCynQ on the Workstation, the Origin and the Relay, and pick the role of each one.

  2. Introduce the nodes

    Export a node file on each computer and import it on its neighbours. RCynQ allows the keys itself.

  3. Pull and send

    Run the diagnostics, press Pull, edit a file, press Send changes. Done.

Step by step: the setup guide walks through every command, for Windows, Linux and macOS.
